# Инструкция по настройке Supabase (Phase D)
## Lead Hunter Kazakhstan — Cloud CRM & Authentication

Данная инструкция описывает шаги по подключению защищённой облачной базы данных PostgreSQL и системы аутентификации Supabase к проекту Lead Hunter Kazakhstan.

---

### 1. Создание проекта на Supabase

1. Перейдите на официальный сайт [supabase.com](https://supabase.com/) и войдите в свой аккаунт (или зарегистрируйтесь через GitHub/Email).
2. Нажмите кнопку **«New Project»**.
3. Укажите параметры проекта:
   - **Name:** `lead-hunter-kz` (или любое желаемое имя).
   - **Database Password:** Сгенерируйте надёжный пароль и сохраните в менеджере паролей.
   - **Region:** Выберите ближайший регион (например, `Central EU (Frankfurt)` для минимального пинга до Казахстана).
   - **Pricing Plan:** Выберите **Free Plan** ($0/месяц — включает 500 МБ БД, до 50 000 активных пользователей в месяц).
4. Дождитесь завершения развёртывания проекта (обычно 1-2 минуты).

---

### 2. Получение ключей и настройка `.env`

1. В левом меню панели управления Supabase перейдите в раздел **Project Settings** (значок шестерёнки) $\to$ **API**.
2. Скопируйте два значения:
   - **Project URL:** `https://xxxxxxxxxxxxxxxx.supabase.co`
   - **Project API Keys $\to$ `anon` / `public`:** длинный JWT-токен (начинается с `eyJhbGciOi...`).
3. Создайте в корне проекта файл `.env.local` (или добавьте переменные в Vercel Dashboard):
   ```env
   VITE_SUPABASE_URL=https://xxxxxxxxxxxxxxxx.supabase.co
   VITE_SUPABASE_ANON_KEY=eyJhbGciOi...
   ```
   > ⚠️ **КРИТИЧЕСКИ ВАЖНО:** Используйте **только публичный `anon` ключ**. Никогда не копируйте и не вставляйте `service_role` ключ в клиентский код или файлы `.env*`.

---

### 3. Применение SQL-миграций

1. В панели управления Supabase перейдите в раздел **SQL Editor** (значок терминала в левом меню).
2. Нажмите **«New query»**.
3. Откройте файл миграции из репозитория: `supabase/migrations/20261013000000_init_schema.sql`.
4. Скопируйте всё содержимое файла и вставьте в окно SQL Editor.
5. Нажмите кнопку **«Run»** (или сочетание `Ctrl + Enter`).
6. Убедитесь, что в результате отобразилось сообщение: `Success. No rows returned`.
7. Перейдите в раздел **Table Editor** и убедитесь, что созданы таблицы:
   - `profiles`
   - `leads`
   - `user_settings`
   - Рядом с каждой таблицей горит индикатор **RLS Enabled** (зелёный щит).

---

### 4. Настройка Authentication (Аутентификации)

1. В левом меню перейдите в раздел **Authentication** $\to$ **Providers** $\to$ **Email**.
2. Проверьте параметры:
   - **Enable Email provider:** Включено (ON).
   - **Confirm email:** 
     - Для быстрого локального тестирования можно временно отключить (OFF), тогда пользователи смогут входить сразу без перехода по ссылке из почты.
     - Для production рекомендуется включить (ON).
3. Перейдите в раздел **Authentication** $\to$ **URL Configuration**:
   - **Site URL:**
     - Для локальной разработки: `http://localhost:5173`
     - Для продакшена: `https://ваш-домен.vercel.app`
   - **Redirect URLs:** Добавьте:
     - `http://localhost:5173/**`
     - `https://ваш-домен.vercel.app/**`

---

### 5. Проверка Row Level Security (RLS)

Политики RLS в файле миграции гарантируют полную изоляцию данных:
- Запрос `SELECT FROM leads` всегда фильтруется по `auth.uid() = user_id`.
- Даже если злоумышленник отправит запрос к Supabase REST API с чужим `id`, база данных отклонит операцию на уровне ядра PostgreSQL.
- Публичные таблицы отсутствуют.

---

### 6. Миграция существующих лидов из localStorage

Когда пользователь входит в свой аккаунт в Lead Hunter Kazakhstan:
1. Система автоматически проверяет, есть ли в `localStorage` ранее сохранённые лиды.
2. При наличии локальных данных открывается окно безопасной миграции.
3. Пользователь может:
   - Скачать CSV-бэкап перед началом.
   - Нажать «Импортировать в облако» (все лиды со статусами, скорингом и историей переносятся в PostgreSQL).
   - Локальная копия в браузере не стирается, предотвращая потерю данных при сбоях сети.
